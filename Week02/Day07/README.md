## 3. 핵심 개념

### 3.1 조합논리와 순차논리

조합논리의 출력은 현재 입력으로 결정된다. 순차논리는 이전에 저장한 상태까지 사용한다.
래치와 플립플롭은 모두 상태를 저장하지만 값을 받아들이는 시점이 다르다.

| 구분 | Positive-level D latch | Positive-edge DFF |
|---|---|---|
| 데이터를 받아들이는 조건 | enable이 1인 동안 | clk의 상승 에지 |
| 조건 만족 중 d 변경 | q가 d를 따라감 | 다음 상승 에지까지 유지 |
| 그 외 구간 | 이전 q 유지 | 이전 q 유지 |
| SV 의도 표현 | always_latch | always_ff @(posedge clk) |

래치의 제어 신호는 강의에서 clock으로 표기되지만, 실습에서는 역할을 분명히 하려고 en으로 이름 붙여도 된다.
래치는 의도적으로 사용할 수도 있다. 문제가 되는 것은 조합논리를 만들려다 실수로 저장소자를 추론하는 경우다.

### 3.2 의도한 래치와 의도하지 않은 래치

다음은 완성 모듈이 아닌 동작을 읽기 위한 핵심 부분이다.

```verilog
always @(*) begin
    if (en)
        q = d;
end
```

en=0에서 q에 새 값을 쓰지 않으므로 이전 값을 유지해야 한다. 이것이 래치 동작이다.
조합회로를 의도했다면 else 또는 기본 할당으로 모든 경로의 값을 정해야 한다.

```verilog
always @(*) begin
    y = 1'b0;
    if (en)
        y = d;
end
```

두 번째 코드는 블록이 실행될 때 y에 먼저 0을 할당하고, en=1이면 d로 덮어쓴다.
따라서 en=1이면 y=d, en=0이면 y=0이다. 아래처럼 else를 쓰는 것과 같은 기능이다.

```verilog
always @(*) begin
    if (en)
        y = d;
    else
        y = 1'b0;
end
```

조합논리를 만들려면 기본값 또는 else로 모든 경우를 할당한다.
반대로 래치를 만들 목적이라면 en=0에서 이전 값을 유지해야 하므로 0을 할당하지 않는다.
예를 들어 1을 저장한 뒤 en=0으로 내리면 래치는 1을 유지하지만, 기본값을 준 조합회로는 0으로 바뀐다.

### 3.3 DFF와 Nonblocking

```verilog
always @(posedge clk)
    q <= d;
```

상승 에지에서 d를 평가하고 q의 갱신을 예약한다. 클록이 1인 구간 전체에서 d를 따라가는 회로가 아니다.
reg 또는 logic이라는 선언만으로 FF가 결정되지는 않는다. 이벤트 조건과 할당 구조를 함께 봐야 한다.

### 3.4 q_bar는 무엇의 반전인가?

```verilog
// 현재 저장 상태 q의 반전
assign q_bar = ~q;
always @(posedge clk)
    q <= d;
```

```verilog
// 비교 대상: 에지 직전 q의 반전을 별도 레지스터에 저장
always @(posedge clk) begin
    q <= d;
    q_bar <= ~q;
end
```

두 번째에서는 두 우변을 갱신 전 값으로 평가한다. 따라서 q는 새 d를 받고 q_bar는 **이전 q의 반전**을 받는다.
새 q의 반전과 항상 같지는 않다. 예를 들어 에지 전 q=0, 그 에지의 d=1이면 갱신 후 q=1, q_bar=1이다.

교재 11.9(a)의 q<=d, q_bar<=~d는 같은 에지의 d로 두 값을 계산한다. 이것과 11.10의 q_bar<=~q를 혼동하지 않는다.
오늘은 저장 동작 차이를 먼저 이해한다. 실제 자원 수 비교는 선택 실습이다.

### 3.5 Blocking/Nonblocking과 순서

```verilog
// A: 앞 문장의 갱신 결과를 다음 문장에서 사용
q0 = d;
q1 = q0;

// B: 두 우변 모두 에지 직전 값으로 평가
q0 <= d;
q1 <= q0;
```

A에서는 같은 블록 실행 중 q1까지 새 d가 전달된다. B에서는 q1이 이전 q0를 받으므로 저장 단계가 생긴다.
Blocking 문장을 역순으로 쓰면 이전 값을 참조하는 구조가 될 수 있다.
Nonblocking은 이 예제처럼 서로 다른 변수에 한 번씩 할당할 때 문장 순서를 바꿔도 같은 동작을 표현한다.
같은 변수에 여러 번 할당하는 경우까지 일반화하지 않는다.

```verilog
// 같은 블록, 같은 시각에 같은 변수로 두 번 예약하면 마지막 할당이 적용된다.
q <= a;
q <= b;
```

이 경우 q는 b가 된다. 서로 다른 always 블록의 경합까지 이 규칙으로 해석하지 않는다.

## 4. 직접 작성할 RTL / Testbench

### 4.1 래치와 DFF 비교 — 필수

| 작성할 파일 | 역할 |
|---|---|
| rtl/dlatch.v | en=1일 때 d 전달, en=0일 때 유지 |
| rtl/dff.v | 상승 에지에서 d 저장 |
| tb/tb_dlatch_dff.v | 공통 입력을 넣고 두 출력 비교 |

강의 코드 11.1과 11.8을 참고해서 포트부터 직접 작성한다.
TB에서는 clk를 0으로 초기화하고 10ns마다 반전시킨다. 비교용 래치 en에는 같은 clk를 연결한다.
d는 상승 에지와 겹치지 않게 변경한다.
현재 작성한 dlatch는 d/en 입력만, dff는 d/clk 입력만 갖는다.
래치의 en에는 clk를 연결하고, DFF에는 별도 en 없이 q<=d를 사용했다.
DFF의 en에 clk를 연결하면 매 상승 에지에서 en도 1이어서 독립적인 Enable 테스트가 되지 않는다.
실제 Vivado 파일 맨 위에는 다음 시간 단위가 이미 선언되어 있다. 채팅 코드에서는 생략했으며 중복 작성할 필요는 없다.

```verilog
`timescale 1ns/1ps
```

| 시각 | clk / 입력 동작 | 예상 래치 q | 예상 DFF q |
|---|---|---|---|
| 0ns | clk=0, d=0 | 초기 X 가능 | 초기 X 가능 |
| 5ns | d=1 | 유지 | 유지 |
| 10ns 직후 | clk 상승 | 1 | 1 |
| 15ns | clk=1 중 d=0 | 0으로 변경 | 1 유지 |
| 20ns | clk 하강 | 0 유지 | 1 유지 |
| 25ns | clk=0 중 d=1 | 0 유지 | 1 유지 |
| 30ns 직후 | clk 상승 | 1 | 1 |

리셋 없는 저장소자는 초기 X가 정상적으로 나타날 수 있다. 최초 유효 입력 전달/에지 이후부터 정답을 비교한다.
TB에는 명시적 wire 출력 선언과 유한 종료 시점($finish)을 넣는다.

### 4.2 기본 할당 유무 비교 — 코드·파형 확인

**목표:** en=0에서 이전 값을 유지하는 래치와 0을 출력하는 조합회로를 비교한다. clk는 필요 없다.

| 모듈 | always @(*) 내부 | en=0 동작 |
|---|---|---|
| latch_bad | if(en) y=d; | 이전 y 유지 |
| comb_fixed | y=1'b0; 이후 if(en) y=d; | y=0 |

작성한 두 번째 모듈의 이름은 latch였지만 기능은 조합논리다. comb_fixed로 바꾸면 이름과 역할이 맞는다.
latch_bad는 조합회로를 의도했는데 래치를 추론한 상황을 가정한 이름이며 문법 오류라는 뜻은 아니다.
TB에서 동일한 d/en을 두 모듈에 연결하고 출력은 y_bad/y로 분리했다.

```verilog
initial begin
    en = 1; d = 1;
    #10 en = 0;
    #10 d = 0;
    #10 d = 1;
    #10 en = 1;
    #10 $finish;
end
```

| 시각 | en | d | y_bad | y |
|---|---|---|---|---|
| 0ns 입력 반영 후 | 1 | 1 | 1 | 1 |
| 10ns | 0 | 1 | 1 유지 | 0 |
| 20ns | 0 | 0 | 1 유지 | 0 |
| 30ns | 0 | 1 | 1 유지 | 0 |
| 40ns | 1 | 1 | 1 | 1 |

학습 대화에 올린 파형에서 위 동작을 확인했다.
특히 20ns에 d가 0이 되어도 y_bad는 1을 유지했다. 합성은 필수가 아니며 선택 안내는 7번을 참고한다.

### 4.3 q/q_bar 비교 — 다음에 진행할 실습

**목표:** 현재 q를 반전하는 출력과 에지 직전 q를 반전해서 저장하는 출력의 차이를 확인한다.

1. rtl/dff_qbar.v: posedge clk에서 q<=d, 블록 밖에서 assign q_bar=~q.
2. rtl/dff_qbar_prev.v: posedge clk 블록 안에 q<=d와 q_bar<=~q.
3. TB에서 같은 clk/d를 두 모듈에 연결하고 출력은 각각 분리한다.
4. 상승 에지 전에 d를 0, 1, 0 순서로 설정하고 에지 후 값을 비교한다.

첫 에지에서 d=0을 저장한 뒤 다음 에지에서 d=1을 넣으면,
두 모듈의 새 q는 모두 1이다. 그러나 assign 방식 q_bar는 0,
별도 저장 방식 q_bar는 이전 q=0의 반전인 1이다.
이 차이가 보이는지 확인한다. 아직 이 실습의 실행 결과는 미확인이다.

### 4.4 할당 방식·순서 비교 — 세 구현의 코드·파형 확인

**목표:** 같은 q0/q1/q2/q3를 사용해도 할당 방식과 순서에 따라 데이터 전달 단계가 달라짐을 확인한다.
참고: 20.pdf 코드 11.16~11.17.

| 작성한 모듈 | 블록 내부 순서 | 확인한 출력 |
|---|---|---|
| shift_assignment_compare | q0=d; q1=q0; q2=q1; q3=q2; | q3_0: 같은 에지에 새 d 전달 |
| shift_assignment_compare_1 | q3=q2; q2=q1; q1=q0; q0=d; | q3_1: 에지마다 한 단계 이동 |
| shift_assignment_compare_2 | q0<=d; q1<=q0; q2<=q1; q3<=q2; | q3_2: 에지마다 한 단계 이동 |

TB는 clk=0에서 시작해 10ns마다 반전시켰다. d는 5, 15, 25ns처럼 에지 사이에서 변경했다.
아래는 각 상승 에지의 갱신이 끝난 뒤 값이다.

| 상승 에지 | 샘플된 d | q3_0 | q3_1 | q3_2 |
|---|---|---|---|---|
| 10ns | 1 | 1 | X | X |
| 30ns | 0 | 0 | X | X |
| 50ns | 1 | 1 | X | X |
| 70ns | 1 | 1 | 1 | 1 |
| 90ns | 0 | 0 | 0 | 0 |

10ns에 q0로 들어온 1은 30ns에 q1, 50ns에 q2, 70ns에 q3로 이동한다.
입력을 받는 에지를 포함하면 네 번째 에지에 출력되며 시간 차이는 3클록 주기(60ns)다.
q3_1과 q3_2가 같은 파형인 것을 확인했다. 초기 X는 리셋 없는 내부 상태가 아직 채워지지 않아 나타난다.

**Nonblocking 역방향은 원리를 이해했으므로 반복 실행을 필수로 요구하지 않는다.**

```verilog
q3 <= q2;
q2 <= q1;
q1 <= q0;
q0 <= d;
```

각 우변은 해당 블록 실행에서 갱신 전 값을 사용하므로 정방향과 같은 4단 시프트 동작이다.
이는 서로 다른 변수에 각각 한 번씩 Nonblocking 할당하는 이번 구조에 대한 설명이다.
같은 변수에 중복 할당하면 마지막 할당이 적용되는 예외는 3.5절을 참고한다.

19.pdf 코드 11.4~11.7 및 20.pdf 코드 11.13~11.15의 추가 비교는 선택이다.
래치 Nonblocking 예제는 감지신호목록과 델타 사이클까지 영향을 줄 수 있어 이번 시프트 레지스터와 구분한다.

## 5. SystemVerilog 추가 실습

Verilog가 동작한 뒤 동일 포트의 dlatch_sv.sv, dff_sv.sv를 직접 작성한다.

```systemverilog
// 의도한 저장 동작: 래치
always_latch begin
    if (en)
        q <= d;
end

// 의도한 저장 동작: 플립플롭
always_ff @(posedge clk) begin
    q <= d;
end
```

- logic: 0/1/X/Z를 표현하는 4상태 변수형. 저장소자 종류를 정하는 키워드는 아니다.
- always_latch: 래치 의도를 명시한다. @(*)를 덧붙이지 않는다.
- always_ff: 클록 이벤트를 명시한다. 같은 출력 변수를 다른 절차 블록에서 중복 구동하지 않는다.
- 래치에서 이전 값을 유지하는 경로는 의도한 동작이다. always_comb의 누락 할당과 구분한다.

**TB 자동 비교는 Day06의 assert를 재사용한다.**

```systemverilog
@(negedge clk);
d = 1'b1;
@(posedge clk);
#1;
assert (q_v === q_sv)
    else $fatal(1, "Verilog/SV mismatch");
assert (q_sv === d)
    else $fatal(1, "DFF expected value mismatch");
```

첫 assert는 구현끼리 비교, 두 번째는 정답값과 비교한다. 이 구간에서는 d를 다음 에지까지 유지한다.
#1은 FF의 물리적 지연을 정의하는 것이 아니라 Nonblocking 갱신 뒤 값을 읽기 위한 TB 대기다.
TB에 이미 선언된 시간 단위가 1ns/1ps이므로 여기의 #1은 1ns다.
래치 검사는 en이 열린 동안 d를 바꾼 뒤와, 닫힌 동안 d를 바꾼 뒤를 나누어 수행한다.

### 5.1 DFF 자동 검증 — 2건 PASS

작성한 tb_dff_sv에서는 기존 dff와 dff_sv에 같은 clk/d를 연결했다.
하강 에지에서 d를 설정하고 다음 상승 에지 후 #1 뒤에 검사한다.
q_v===q_sv는 두 구현의 일치, q_sv===d는 정답값과의 일치를 검사한다.
1 저장과 0 저장을 각각 검사하여 총 2건 PASS를 확인했다.

| 구문 | 의미 |
|---|---|
| @(negedge clk); | 하강 에지까지 대기 |
| @(posedge clk); | 다음 상승 에지까지 대기 |
| #1; | Nonblocking 갱신 후 검사하도록 1ns 대기 |
| assert (...) else $fatal(...) | 조건이 거짓이면 메시지 출력 후 종료 |

TB의 q_v/q_sv는 wire 또는 logic으로 선언할 수 있다. 이번에는 각각 모듈 출력 하나가 구동하므로 logic도 가능하다.
여러 드라이버의 값을 해석하는 net 연결까지 모든 wire를 logic으로 바꿀 수 있다는 뜻은 아니다.

### 5.2 래치 자동 검증 — 남은 실습

latch_sv는 always_latch에서 en=1일 때 q<=d로 작성했다.
현재 DFF TB에는 연결하지 않았으므로 래치까지 검증된 것은 아니다.
별도 TB에서 기존 dlatch와 latch_sv에 같은 d/en을 연결하고 각 입력 변경 후 #1 뒤에 검사한다.

| 순서 | 입력 | 예상 q |
|---|---|---|
| 1 | en=1, d=0 | 0 |
| 2 | en=1, d=1 | 1 |
| 3 | en=0, d=0 | 이전 값 1 유지 |
| 4 | en=1, d=0 | 0 |

3번에서는 q를 현재 d와 비교하면 안 된다. 래치가 닫혀 있으므로 저장한 정답값 1과 비교한다.

## 6. Python / C 연계

**Python은 선택:** 오늘은 새 자동화 파일을 필수로 만들지 않는다.
간단히 이전 상태를 사용하는 갱신만 복습하려면 다음 예측 모델을 직접 실행해 본다.

```python
q = 0
for d in [0, 1, 0, 1]:
    old_q = q
    q = d
    q_bar_prev = 1 - old_q
    print(d, q, q_bar_prev)
```

old_q는 에지 직전 상태를 보관한다. 0/1 한 비트에서 1-old_q는 반전값이다.
Python은 줄 순서대로 즉시 대입하므로 이전 값을 별도로 보관한 것이다. X/Z나 HDL 이벤트를 재현하는 시뮬레이터는 아니다.
출력 예측만으로 RTL 검증 완료를 표시하지 않는다.

**C:** 이번에는 진행하지 않는다. ARM Software 단계에서 연계한다.

## 8. 에러 및 해결

이번 실습에서 공유한 코드·파형에 기능 오류는 없었으며, 불필요한 포트와 헷갈렸던 개념을 다음과 같이 정리했다.

- **발생한 문제:**
  - 래치 모듈에 사용하지 않는 clk 입력을 선언함.
  - 기본 DFF에 en을 추가하고 clk와 연결하여 Enable 역할이 불명확했음.
  - 기본값 할당과 래치의 이전 값 유지 차이, Blocking/Nonblocking 순서에 따른 동작 차이를 이해하는 데 혼동이 있었음.

- **원인:**
  - 래치의 레벨 제어 입력 en과 DFF의 에지 제어 입력 clk를 같은 포트 구성으로 작성함.
  - DFF의 en에 clk를 연결하면 상승 에지마다 en=1이 되어 독립적인 Enable 기능을 시험할 수 없음.
  - 조합회로의 기본값 할당과 저장소자의 상태 유지, 즉시 할당과 갱신 예약의 차이를 구분할 필요가 있었음.

- **수정한 RTL/TB 코드:**
  - dlatch는 d/en 입력만 사용하도록 미사용 clk 포트 제거.
  - 기본 dff는 d/clk 입력만 두고 if(en)을 제거하여 상승 에지에서 q<=d를 수행.
  - 기본값 비교에서는 y=1'b0을 먼저 할당하고 en=1이면 y=d로 덮어쓰는 조합회로를 래치와 비교.
  - 동일한 입력과 클록으로 Blocking 정방향·역방향, Nonblocking 정방향을 각각 실행해 출력 비교.

- **변경 전후 결과:**
  - 불필요한 포트를 정리한 뒤에도 래치 / DFF의 의도한 동작이 유지됨을 확인.
  - en=0에서 값을 할당하지 않으면 이전 값 유지, 기본값을 주면 0 출력이라는 차이를 확인.
  - Blocking 정방향은 같은 에지에 새 입력이 전달되고, 역방향과 Nonblocking 정방향은 저장 단계마다 이동함을 확인.
  - Nonblocking은 이번처럼 서로 다른 변수에 한 번씩 할당할 때 순서를 바꿔도 같으며, 같은 변수에 여러 번 할당하면 마지막 할당이 적용됨을 정리.

**시간 단위:** 실제 Vivado 파일 맨 위에는 이미 다음 선언이 있으며, 채팅에 코드를 붙일 때만 생략했다. 누락 오류나 추가 수정 사항이 아니다.

```verilog
`timescale 1ns/1ps
```

따라서 해당 파일의 #10은 10ns, #1은 1ns를 의미한다.
