## 3. 핵심 개념

### 3.1 Active-low와 동기·비동기는 다른 구분이다

- Active-low: rst_n=0일 때 리셋 활성화.
- 동기 리셋: 상승 에지에서만 리셋을 검사.
- 비동기 리셋: 상승 에지가 없어도 rst_n의 하강 에지에서 리셋을 수행.
- rst_n=1로 해제했다고 바로 d를 저장하지는 않는다. 정상 데이터 저장은 다음 상승 에지에서 이루어진다.

| 상황 | 동기 리셋 DFF | 비동기 리셋 DFF |
|---|---|---|
| 에지 사이에 rst_n=0 | 다음 상승 에지까지 기존 q 유지 | q를 0으로 갱신 |
| rst_n=0에서 상승 에지 | q=0 | q=0 |
| 에지 사이에 rst_n=1 | 즉시 데이터 저장하지 않음 | 즉시 데이터 저장하지 않음 |
| 에지 사이에 시작·종료한 짧은 리셋 | 상승 에지에 걸리지 않으면 놓침 | 활성화 시 q=0 |

실제 하드웨어의 비동기 리셋 해제에는 recovery/removal 타이밍과 동기화 고려가 필요하다.
이번에는 RTL 기능 비교에 집중하고 입력을 클록 에지와 겹치지 않게 준다.

### 3.2 코드에서 달라지는 부분

완성 모듈을 복사하기 전에 아래 핵심 부분을 읽고, 입력 d/clk/rst_n과 출력 q를 직접 선언한다.

```verilog
// 동기 리셋
always @(posedge clk) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end
```

```verilog
// 비동기 리셋
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end
```

if 조건이 같아도 실행되는 이벤트가 다르다.
비동기 리셋은 감지 조건에 negedge rst_n이 있고, 동기 리셋은 clk 상승 에지만 있다.
리셋을 가장 먼저 검사하면 리셋이 Enable이나 데이터보다 우선한다.

### 3.3 Enable에서 else가 없어도 되는 이유

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= 8'd0;
    else if (en)
        cnt <= cnt + 8'd1;
end
```

en=0이면 기존 FF 값을 유지한다. 이 에지 기반 블록에서 else가 없다고 래치가 생기는 것은 아니다.
Day07의 always @(*)에서 불완전 할당으로 래치가 생긴 경우와 구분한다.

### 3.4 8비트 카운터의 순환

8비트 unsigned는 0~255를 표현한다.
255에서 1을 더한 결과를 8비트에 저장하면 상위 자리올림이 빠져 0이 된다.

| 동작 | 이전 값 | 다음 값 |
|---|---|---|
| 증가 | FE | FF |
| 증가 | FF | 00 |
| 감소 — 선택 | 00 | FF |

### 3.5 PDF 21의 코딩 지침

순차회로의 상태 갱신은 Nonblocking, 조합논리 계산은 Blocking을 기본으로 사용한다.
오늘 실습에서는 한 블록 안에서 두 할당 방식을 섞지 않고, 동일 상태 변수를 여러 always 블록에서 구동하지 않는다.
간단한 조합식은 q<=a&b처럼 직접 사용하거나 assign으로 분리할 수 있다.
이 지침은 학습용 기본 규칙이며 Blocking 사용 자체가 문법 오류라는 뜻은 아니다.

## 4. Verilog 직접 작성 실습

### 4.1 리셋 DFF 두 개 만들기

| 작성할 파일 | 포트 / 역할 |
|---|---|
| rtl/dff_sync_rst.v | d, clk, rst_n → q / 동기 리셋 |
| rtl/dff_async_rst.v | d, clk, rst_n → q / 비동기 리셋 |
| tb/tb_dff_reset_compare.v | 동일 clk/d/rst_n 연결, 출력 q_sync/q_async 분리 |

출력은 Verilog의 output reg로 선언하고 3.2절의 블록을 참고한다.
TB에서 clk=0으로 시작해 10ns마다 반전시킨다.
아래 입력 순서를 직접 작성한다. 누적 시간과 #지연을 구분한다.

```verilog
initial begin
    rst_n = 0; d = 1;
    #15 rst_n = 1;
    #20 rst_n = 0;  // 35ns
    #10 rst_n = 1;  // 45ns
    #10 rst_n = 0;  // 55ns: 짧은 펄스 시작
    #10 rst_n = 1;  // 65ns: 다음 상승 에지 전에 해제
    #10 $finish;   // 75ns
end
```

| 시각 | 동작 | 예상 q_sync | 예상 q_async |
|---|---|---|---|
| 0ns | rst_n=0 | 첫 상승 에지 전 X 가능 | 리셋 처리 후 0 |
| 10ns | 상승 에지, 리셋 활성 | 0 | 0 |
| 15ns | 리셋 해제 | 0 유지 | 0 유지 |
| 30ns | 상승 에지, d=1 | 1 | 1 |
| 35ns | 에지 사이 리셋 활성 | 1 유지 | 0 |
| 45ns | 리셋 해제 | 1 유지 | 0 유지 |
| 50ns | 상승 에지 | 1 | 1 |
| 55ns | 짧은 리셋 시작 | 1 유지 | 0 |
| 65ns | 짧은 리셋 해제 | 1 유지 | 0 유지 |
| 70ns | 상승 에지 | 1 | 1 |

35~45ns, 55~65ns의 리셋 펄스는 모두 상승 에지에 걸리지 않는다.
동기 리셋이 에지에서 실제 적용되는 경우는 초기 10ns에서 확인한다.
추가로 리셋을 30ns부터 바꾸지 말고, 예를 들어 35~55ns로 유지해 50ns 상승 에지에서 두 출력이 0이 되는 경우도 시험할 수 있다.

### 4.2 8비트 증가 카운터

코드 11.26을 참고하여 rtl/counter_up.v를 작성한다.
입력 clk/rst_n, 출력 reg [7:0] cnt를 선언하고 Active-low 비동기 리셋을 사용한다.
리셋이면 0, 아니면 상승 에지마다 1 증가한다.

TB에서 첫 상승 에지가 리셋 활성 구간에 들어가도록 rst_n=0으로 시작하고 15ns에 해제한다.
30ns부터 cnt가 1, 2, 3 순서로 증가하는지 확인한다.
리셋이 없는 상태에서 시작해 X에 1을 계속 더하지 않도록 한다.

### 4.3 Enable 추가

rtl/counter_up_en.v를 따로 작성한다. 기존 counter_up은 보존한다.
추가 입력 en이 1일 때만 증가시키고, 리셋이 Enable보다 우선하도록 만든다.
두 카운터는 서로 다른 명세이므로 en=0일 때 서로 다르다는 이유로 실패 처리하지 않는다.

| 테스트 | 입력 / 조작 | 확인할 내용 |
|---|---|---|
| 리셋 | rst_n=0, en=0 | cnt=0 |
| 정상 증가 | rst_n=1, en=1 | 매 상승 에지 +1 |
| 일시정지 | 하강 에지에서 en=0 | 여러 상승 에지 동안 유지 |
| 재개 | 하강 에지에서 en=1 | 유지하던 값에서 +1 |
| 리셋 우선 | en=0, cnt가 0이 아닐 때 에지 사이 rst_n=0 | 클록 없이도 0 |
| 순환 | 리셋 해제 후 en=1로 256회 상승 에지 | FF 다음 00 |

입력은 하강 에지에서 설정하고, 검사할 때는 상승 에지 후 #1을 둔다.
Enable=0에서 0을 새로 쓰는 것이 아니라 현재 카운트 값을 유지한다는 점에 주의한다.

## 5. SystemVerilog 추가 실습

counter_up_en을 counter_up_en_sv.sv로 옮긴다.
포트는 logic, 상태 갱신은 다음 형태로 사용한다.

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= 8'd0;
    else if (en)
        cnt <= cnt + 8'd1;
end
```

TB에서 Verilog와 SV 카운터를 같은 입력에 연결하고 cnt_v/cnt_sv를 분리한다.
이번에는 DFF와 달리 정답이 단순히 입력 d가 아니므로, **8비트 expected 변수**로 이전 정답을 보관한다.

아래는 리셋을 마치고 en=1로 연속 증가시키는 구간의 예시 조각이다.
초기 리셋 상승 에지를 한 번 지난 후 하강 에지에서 rst_n=1, en=1을 설정하고 expected=0으로 맞춘 다음 실행한다.
이 반복 구간에서는 rst_n/en을 변경하지 않는다.

```systemverilog
repeat (256) begin
    @(posedge clk);
    expected = expected + 8'd1;
    #1;
    assert (cnt_v === cnt_sv)
        else $fatal(1, "Verilog/SV mismatch");
    assert (cnt_sv === expected)
        else $fatal(1, "Counter expected value mismatch");
end
```

- repeat(256): 내부 절차를 256번 반복한다. 에지를 기다리므로 256개 클록 이벤트를 검사한다.
- logic [7:0] expected: 8비트여서 FF 다음 00으로 순환한다.
- TB의 expected는 검사 계산용 변수이므로 Blocking으로 갱신한다.
- 실제 DUT의 cnt는 Nonblocking으로 갱신하며 #1 뒤에 읽는다.
- Enable 정지 검증에서는 expected를 증가시키지 않고 유지한다.
- 비동기 리셋 검증에서는 에지 사이에 rst_n=0을 넣고 #1 뒤에 cnt=0을 검사한다. 다음 상승 에지만 기다리면 비동기 반응 시점을 검증하지 못한다.

먼저 Verilog로 파형을 이해한 뒤 이 검사를 추가한다. 초기부터 task나 class를 새로 도입하지 않는다.

## 6. Python / C 및 선택 확장

### Python — 짧은 계산만 선택

```python
cnt = 254
for _ in range(3):
    cnt = (cnt + 1) & 0xFF
    print(cnt)
```

실행 결과는 `255 → 0 → 1`이었다. Python 참조 모델로 계산한 기대값을 Vivado 파형의 `FF → 00 → 01`과 대조했다.
Python 정수는 자동으로 8비트에 제한되지 않으므로 & 0xFF로 하위 8비트만 남긴다.
_는 이번 반복에서 사용하지 않는 변수 이름이라는 관례다.
이 계산만으로 RTL 검증이 완료되는 것은 아니다.

### 리셋 DFF 비교 — 실제 입력과 결과

clk는 0으로 시작하여 10ns마다 반전하고 d=1을 유지했다.
rst_n은 1로 시작해 1~2ns, 28~32ns 동안 0으로 설정했다.

| 시각 | 동작 | q_sync | q_async |
|---|---|---|---|
| 0ns | 초기 상태 | X | X |
| 1ns | 리셋 활성 | X 유지 | 0 |
| 2ns | 리셋 해제 | X 유지 | 0 유지 |
| 10ns | 상승 에지 | 1 | 1 |
| 28ns | 리셋 활성 | 1 유지 | 0 |
| 30ns | 리셋 중 상승 에지 | 0 | 0 |
| 32ns | 리셋 해제 | 0 유지 | 0 유지 |
| 50ns | 상승 에지 | 1 | 1 |

### 8비트 증가 카운터 — 실제 입력과 결과

rst_n은 1로 시작해 1~15ns, 75~85ns 동안 0으로 설정했다.

| 시각 | 동작 | cnt |
|---|---|---|
| 1ns | 비동기 리셋 | 0 |
| 10ns | 리셋 중 상승 에지 | 0 유지 |
| 30/50/70ns | 정상 증가 | 1 / 2 / 3 |
| 75ns | 에지 사이 비동기 리셋 | 즉시 0 |
| 85ns | 리셋 해제 | 0 유지 |
| 90/110ns | 정상 증가 | 1 / 2 |

### Enable 카운터 — 실제 코드와 결과

```verilog
module counter_up_en(
    input wire clk, rst_n, en,
    output reg [7:0] cnt
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            cnt <= 8'b0;
        else if (en)
            cnt <= cnt + 8'd1;
    end
endmodule
```

```verilog
initial begin
    rst_n = 1; en = 1;
    #1  rst_n = 0;
    #14 rst_n = 1;  // 15ns
    #34 en = 0;     // 49ns
    #3  en = 1;     // 52ns
    #40 rst_n = 0;  // 92ns
    #10 rst_n = 1;  // 102ns
    #40 $finish;    // 142ns
end
```

| 시각 | 동작 | cnt |
|---|---|---|
| 1ns | 리셋 | 0 |
| 30ns | en=1에서 증가 | 1 |
| 49ns | en=0 | 1 유지 |
| 50ns | en=0에서 상승 에지 | 1 유지 |
| 52ns | en=1 | 1 유지 |
| 70ns | 증가 재개 | 2 |
| 90ns | 증가 | 3 |
| 92ns | 비동기 리셋 | 0 |
| 102ns | 리셋 해제 | 0 유지 |
| 110/130ns | 정상 증가 | 1 / 2 |

Enable을 0으로 준 구간에 상승 에지가 한 번 포함되어, 그 에지에서 증가를 건너뛰는 것을 확인했다.
여러 상승 에지 동안 유지하는 테스트는 추가로 할 수 있다.

### SystemVerilog 자동 검증

리셋을 40ns에 해제하며 `expected`를 0으로 초기화했다. 50ns의 첫 상승 에지부터 DUT와 기대값이 함께 증가했고, 각 에지에서 1ns 뒤에 출력을 비교했다. 공유한 파형에서 `cnt_v`, `cnt_sv`, `expected`가 `FE → FF → 00 → 01`로 일치했다.

```text
PASS: 512 counter checks
```

이번 자동 검증은 `en=1`로 진행했다. `en=0`에서의 값 유지는 앞선 Verilog 파형에서 확인했고, `en=0`인 상태에서 리셋 우선 동작은 추가 검증 항목이다.
합성·LUT 분석은 선택이며 오늘의 필수 완료 조건이 아니다.

## 8. 에러 및 해결

### 8.1 실제 오류 여부

- **발생한 문제:** 공유한 리셋 DFF·증가 카운터·Enable 카운터 코드와 파형에서 기능 오류는 발견하지 못했다.
- **원인:** 해당 없음.
- **수정한 RTL/TB 코드:** 기능 수정은 필요하지 않았다. 증가 상수는 비트 폭과 의도를 명확히 하도록 `cnt + 8'd1`로 작성했다.
- **변경 전후 결과:** 기존 `cnt + 1`도 이번 8비트 카운터에서는 의도대로 동작했으며, 표기를 명확히 한 뒤에도 증가 동작은 같다.

### 8.2 SV 테스트벤치의 기대값 초기화와 종료

- **발생한 문제** — DUT는 1로 증가했지만 `expected`가 `XX`여서 첫 기대값 비교가 실패했다.
- **원인** — DUT 리셋과 TB 변수의 초기화는 별개다. 초기값 `X`에 1을 더해도 `X`가 유지된다.
- **수정한 RTL/TB 코드** — 리셋 해제 직후 `expected = 8'd0;`을 추가했다. RTL의 `always_ff`에는 `<=`를 적용했고, TB는 반복문 뒤에서 PASS를 출력한 후 `$finish`로 종료했다.
- **변경 전후 결과** — 첫 비교 실패에서 512회 통과로 바뀌었다. `$finish`는 반복 검사가 끝난 뒤에도 클록을 생성하는 시뮬레이션을 정상 종료한다.

### 8.3 학습 중 확인한 내용

- `8'h01`, `8'b1`, `8'd1`은 모두 8비트 값 `0000_0001`이다. 앞의 8이 전체 폭을 정한다.
- 에지 기반 블록에서 `else if (en)` 뒤에 else가 없으면 FF가 값을 유지한다. 래치를 만드는 코드가 아니다.
- `else cnt <= 8'b0;`을 추가하면 en=0인 **상승 에지에서** 0으로 바뀐다. en 하강 즉시 초기화되는 것은 아니다.
- `#34`, `#3` 같은 지연은 이전 지연에 누적된다. Enable 정지 구간은 49~52ns다.
- 시간 단위는 Vivado 실제 파일 상단에 이미 선언되어 있다.

## 9. 학습 내용 및 다음 보완

- **새롭게 이해한 개념:** Active-low는 리셋 극성, 동기·비동기는 리셋이 적용되는 시점의 구분이다. 비동기 리셋도 해제만으로 데이터를 저장하지 않고 다음 상승 에지에서 정상 동작한다.
- **기존에 잘못 알고 있던 부분 / 구분한 내용:** 순차회로에서 else 생략은 값 유지이며, 조합회로의 불완전 할당에 의한 래치 추론과 구분한다. Enable 비활성 시 유지와 0 초기화는 서로 다른 명세다.
- **추가로 공부할 내용:** en=0일 때 리셋 우선 동작, 여러 클록 동안 정지·재개.
