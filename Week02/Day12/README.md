## 4. 시험을 추가하는 순서

### 4.1 짧은 Start — 선행 확인한 내용

rx를 1클록만 Low로 내린 뒤 High로 복귀하고 2비트 시간 이상 기다렸다.

Verilog 파형에서 IDLE→START→IDLE 복귀, bit_index=0, data_buf/rx_data=0 유지, 가짜 Start 구간의 rx_done=0을 확인했다. 이후 정상 Start가 DATA로 이어지는 모습도 관찰했다. 이 예외 입력의 V/SV 자동 검사 결과는 아직 확인하지 않았다.

### 4.2 잘못된 Stop — 다음 실습

먼저 정상 A6을 수신해 rx_data=A6을 만든다. 그다음 다른 값(예: 3C)을 전송하되 Stop을 0으로 준다.

```systemverilog
// Start와 데이터 8비트 전송 후
rx = 1'b0;  // 잘못된 Stop
repeat (CLKS_PER_BIT) @(negedge clk);

rx = 1'b1;  // Idle로 복귀
repeat (2 * CLKS_PER_BIT) @(negedge clk);
```

정상 Stop 코드의 rx=1 부분을 바꾸는 것이며, Stop 앞에 별도 데이터 비트를 추가하지 않는다.

확인할 내용:
- 잘못된 프레임에 대해 rx_done이 발생하지 않는다.
- rx_data는 이전 정상값 A6을 유지한다.
- data_buf는 수신 중인 3C로 바뀔 수 있다. data_buf 유지까지 요구하지 않는다.
- 이후 정상 프레임을 보내면 다시 수신할 수 있다.

현재 RX는 Low가 지속되면 IDLE에서 다시 START를 감지할 수 있다. 잘못된 Stop 직후 반드시 High로 복귀시켜 충분히 기다린다. 오류 구간 전체에서 완료 횟수가 늘지 않는지 검사한다.

### 4.3 연속 프레임

첫 프레임 Stop을 1비트 동안 유지한 직후, 추가 Idle 대기 없이 다음 Start를 보낸다. 예: A6 다음 3C.

완료 시점마다 첫 번째는 A6, 두 번째는 3C인지 확인하고 완료 펄스 총 2회를 검사한다. 기존의 고정 A6 기대값과 done_count==1을 그대로 사용하지 않는다.

### 4.4 수신 중 리셋

Start와 데이터 일부를 전송한 DATA 상태에서 하강 에지에 rst_n=0을 준다. 다음 상승 에지 후 #1에서 상태 IDLE, cnt/bit_index/data_buf/rx_data/rx_done 초기화를 확인한다.

리셋 중 rx도 1로 복귀시킨다. 한 번 이상 상승 에지를 지난 뒤 하강 에지에 리셋을 해제하고 4클록 이상 대기한 후 정상 프레임을 다시 보낸다. 중단된 프레임은 완료되지 않고 새 프레임은 정상 수신돼야 한다.

### 4.5 정상 데이터 패턴

00, FF, 55를 각각 보내 비트 전환이 적거나 반복되는 데이터도 확인한다. 각 테스트는 먼저 단독 실행하고 나중에 통합한다.

## 5. SV 자동 검사의 확장

Day11 검사 블록의 공통 V/SV 출력 비교와 한 클록 펄스 검사는 유지한다.

| 시나리오 | 기대 데이터·완료 |
|---|---|
| 짧은 Start만 | 완료 0회 |
| 정상 A6 후 잘못된 3C Stop | 총 완료 1회, rx_data=A6 유지 |
| 정상 A6 후 정상 3C 연속 | 순서 A6→3C, 완료 2회 |
| 수신 중 리셋 후 정상 55 | 중단 프레임 완료 없음, 리셋 후 55 완료 1회 |

완료가 없음을 확인하려면 시험 시작 전 완료 횟수를 저장하고, 구간 전체를 감시한 후 횟수가 변하지 않았는지 확인한다. 마지막 순간의 rx_done=0만으로는 중간에 발생한 잘못된 펄스를 잡을 수 없다.

리셋 때 done_count를 0으로 만드는 기존 TB에서는 완료 횟수가 리셋 이후 기준으로 집계된다. 시나리오별 집계 범위를 명확히 한다.

검사 시간은 전체 입력 길이보다 길게 늘린다. 입력만 늘리고 기존 repeat 횟수를 유지하면 전송 도중 $finish가 실행될 수 있다. 각 시험의 PASS 문구도 해당 시나리오를 나타내도록 바꾼다.

## 6. 합성과 타이밍

Day11의 조건 정리 전후 자원 수는 LUT 25, FF 40, IO 12, BUFG 1로 같았다. 이는 Day11 기록이며 Day12 실행 결과로 중복 집계하지 않는다.

시뮬레이션의 always #10은 합성용 클록 제약이 아니다. 설계 top의 clk에 XDC로 20ns 주기를 지정한다.

```tcl
create_clock -name sys_clk -period 20.000 [get_ports clk]
```

setup은 데이터를 에지 전에 안정시켜야 하는 시간, hold는 에지 뒤에도 유지해야 하는 시간이다. 타이밍 보고서에서는 제약 적용 여부와 레지스터 간 경로를 먼저 확인한다.

- WNS: setup 경로의 최악 slack. 음수면 해당 setup 제약 위반.
- WHS: hold 경로의 최악 slack. 음수면 해당 hold 제약 위반.
- 합성 결과의 타이밍은 예비 결과다. 배치배선 후 보고서는 실제 배선 영향을 더 반영한다.
- rx는 비동기 입력이다. 시스템 클록 하나만 지정했다고 모든 입출력·CDC 검증이 완료되는 것은 아니다.
- I/O 제약이나 보드 핀 설정 부족으로 구현이 막히면 메시지를 기록하고, 임의의 지연값이나 광범위한 false path로 경고를 숨기지 않는다.

## 7. 검증 결과

선행 확인: 짧은 Start 취소의 Verilog 파형 확인. 나머지는 실행 후 실제 결과와 파형·PASS 로그를 기록한다.

| 시험 | 기대 결과 | 실제 결과 |
|---|---|---|
| 짧은 Start | START→IDLE, 완료 없음 | Verilog 파형 확인 |
| 잘못된 Stop | 완료 없음, 이전 rx_data 유지 | 미실행 |
| 연속 프레임 | 데이터 순서 일치, 완료 2회 | 미실행 |
| DATA 도중 리셋 | 초기화 후 재수신 가능 | 미실행 |
| 00·FF·55 | 기대값 일치 | 미실행 |

합성·타이밍은 도구 버전, top, 소자, 클록 주기, LUT/FF, WNS/WHS와 미제약 경로 여부를 함께 기록한다.
